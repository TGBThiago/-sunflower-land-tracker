# Codebase Structure

**Analysis Date:** 2026-06-16

## Directory Layout

```
sunflower-land-tracker-backup/
├── .planning/               # GSD planning artifacts (codebase docs, ROADMAP, etc.)
├── index.html               # Main application HTML — structure, modal, toast
├── style.css                # Dark theme CSS — layout, components, animations

│   └── sunflower-backup-2026-06-03.json
```

## Directory Purposes

**Root (project root):**
- Purpose: Contains the entire flat SPA — three application files plus ancillary directories
- Contains: HTML, CSS, JS source files, backup directory, site-clone directory
- Key files: `index.html` (entry point), `style.css` (presentation), `script.js` (logic)

**`.planning/`:**
- Purpose: GSD workflow artifacts — codebase maps, phase plans, roadmaps
- Contains: `codebase/` subdirectory with architectural documentation files
- Generated: Yes (by `gsd-map-codebase` and other GSD commands)
- Committed: Yes

**`save/`:**
- Purpose: Stores exported JSON backup files created via "Salvar Backup" button
- Contains: JSON files with shape `{ dados: [...], taxas: {...}, exportadoEm: "ISO string" }`
- Generated: Yes (by user action via `salvarBackup()`)
- Committed: No (user-generated runtime data; content may vary)

**`site-clone/`:**
- Purpose: Contains a cloned README file (not relevant to application architecture)
- Contains: Documentation-only files

## Naming Conventions

**Files:**
- `kebab-case`: `index.html`, `style.css`, `script.js` — lowercase with hyphen separators
- Backup files use: `sunflower-backup-YYYY-MM-DD.json` (auto-generated by `salvarBackup()`)
- CSV exports use: `sunflower-land-YYYY-MM-DD.csv` (auto-generated by `exportarCSV()`)

**HTML IDs:**
- `camelCase` with semantic prefixes/suffixes: `btnAdd`, `btnExport`, `btnSave`, `btnLoad`, `btnClear`, `btnCancelar`, `btnSalvar`
- Descriptive compound names: `modalOverlay`, `modalForm`, `modalTitle`, `editIndex`
- Field-based: `fieldData`, `fieldGold`, `fieldDiamante`, `fieldFlower`, `fieldSaque`, `fieldObs`
- Card-based: `cardPatrimonio`, `cardDolar`, `cardLucro`, `cardMedia`, `cardEstimativa`
- Rate-based: `taxaGold`, `taxaQtdGemas`, `taxaPrecoLote`, `taxaGemaDisplay`, `taxaDolar`

**JavaScript Identifiers:**
- `camelCase` for all variables and functions: `dados`, `taxas`, `renderizar()`, `calcularEntradas()`, `exportarCSV()`
- Portuguese language for business logic names: `dados` (data), `taxas` (rates), `lucro` (profit), `saque` (withdrawal), `excluirRegistro` (delete record)
- UPPER_SNAKE_CASE for localStorage keys: `STORAGE_KEY = 'sl_tracker_dados'`, `RATES_KEY = 'sl_tracker_taxas'`

**CSS Classes:**
- `kebab-case` consistently: `card-value`, `card-label`, `taxas-bar`, `taxa-item`, `taxa-value-calc`, `btn-add`, `btn-csv`, `btn-save`, `btn-load`, `btn-clear`, `btn-edit`, `btn-del`, `table-wrapper`, `empty-msg`, `modal-overlay`, `modal-actions`, `charts-section`, `chart-card`
- Semantic state classes: `.ativo` (active), `.profit`, `.loss`, `.zero`
- BEM-like card variants: `.card-patrimonio`, `.card-dolar`, `.card-lucro`, `.card-media`, `.card-estimativa`

**CSS Custom Properties:**
- `kebab-case` with `--` prefix: `--bg`, `--surface`, `--text2`, `--gold`, `--flower`, `--radius`, `--shadow`

## Where to Add New Code

**New Feature (e.g., new summary metric, new column):**
- Primary code: `script.js` — add computation logic to `calcularEntradas()`, add rendering to `renderizar()` or `atualizarCards()`
- HTML: `index.html` — add new column `<th>` in `<thead>` or new card `<div>` in `<section class="cards">`
- CSS: `style.css` — add styling classes using existing custom properties

**New Component/Module (e.g., chart type, export format):**
- Implementation: Append to `script.js` following existing patterns (function declaration + event binding at module scope)
- Ensure any new DOM elements are added to `index.html` with a `camelCase` id or `kebab-case` class

**New Action Button:**
- HTML: Add `<button class="btn btn-xxx">` inside `<section class="actions">` in `index.html`
- JS: Add `document.getElementById('btnXxx').addEventListener('click', handler)` in `script.js`
- CSS: Optionally add a new gradient/color class in `style.css`

**Utilities:**
- Shared helpers: Add to `script.js` — the file is currently flat with no separation of concerns; prefix utility functions for clarity (e.g., `formatarData()` is the only utility)

**Backup format changes:**
- Modify `salvarBackup()` and `carregarBackup()` in `script.js` — the JSON backup schema is defined inline in both functions
